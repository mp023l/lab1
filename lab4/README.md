# Лабораторная работа №4. Spring Security

Вариант 18 — REST API аукциона коллекционных предметов, примеры Формулы-1.
Основа: существующая лабораторная №2 из Downloads/lab2/lab2. Сохранены пять ресурсов, адреса, GET/POST/PUT/PATCH/DELETE и правила ставок. Добавлены аутентификация, авторизация и постоянное хранение в H2 без Docker. Это отдельная копия проекта.

## Быстрый запуск

Нужна Java 21. Распакуйте архив в обычную папку и запустите `START.cmd`: он ищет Java в JAVA_HOME, PATH и папке .jdks, используемой IntelliJ. Либо выполните вручную:

```powershell
$env:AUCTION_ADMIN_PASSWORD='AdminDemo123!'
java -Djdk.net.unixdomain.tmpdir=. -jar app.jar
```

Адрес API: http://localhost:8080/api. Главной HTML-страницы нет. Учётная запись `admin` создаётся только при первом запуске. Пароль берётся из переменной окружения; START.cmd задаёт показанный учебный пароль, если переменная не задана. При последующих запусках пароль в базе не заменяется.

## IntelliJ IDEA и сборка

Откройте `pom.xml` как Maven-проект, выберите JDK 21. В конфигурации запуска `AuctionApplication` задайте переменную `AUCTION_ADMIN_PASSWORD=AdminDemo123!`, рабочая папка — корень проекта. В VM options укажите `-Djdk.net.unixdomain.tmpdir=.`. Этот параметр включает TCP fallback внутренних соединений Java: он понадобился для обхода ошибки UnixDomainSockets в установленной Windows/Java 21. START.cmd уже содержит параметр. Maven самостоятельно загрузит зависимости; при первой сборке нужен интернет.

```powershell
mvn clean verify
java -Djdk.net.unixdomain.tmpdir=. -jar target/lab2-1.0.0.jar
```

В IntelliJ можно выполнить Maven → Lifecycle → verify, а затем запустить AuctionApplication. Проверяйте в окне сборки число тестов и отсутствие failures/errors. Идентификатор артефакта `lab2` сохранён от исходного проекта.

## Как выполнить HTTP-коллекцию

1. Импортируйте оба JSON-файла из `postman` в Postman.
2. Выберите окружение «Локальный аукцион». Укажите `baseUrl` и фактический `adminPassword`.
3. Откройте Collection Runner и выполните коллекцию целиком по порядку. Cookie jar должен быть включён. Не запускайте коллекцию параллельно сама с собой.
4. Первый запрос получает CSRF-токен и JSESSIONID. Следующие запросы отправляют cookie автоматически, а токен — заголовком `X-CSRF-TOKEN`.
5. Скрипты создают уникальные логины, сохраняют ID и даты. Старые жёстко заданные ID не нужны. Коллекцию можно повторять: создаются новые пользователи. Она демонстрационная и изменяет данные.

Та же коллекция выполняется без Postman, если установлен Node.js 18+:

```powershell
node verify-http.mjs
```

При другом порте задайте `AUCTION_BASE_URL`, например `http://localhost:18084`. Пароль администратора runner берёт из `AUCTION_ADMIN_PASSWORD` либо из JSON-окружения. Проверки коллекции одинаковы в обоих способах; вспомогательный runner поддерживает используемые здесь скрипты, а не весь API Postman.

Вариант для IntelliJ IDEA — `requests.http`: задайте переменные в начале файла и выполните Run All Requests. Нужна версия IDEA с поддержкой HTTP Client. Файл содержит соответствующие запросы и проверки; автоматическая проверка этой поставки выполнялась через Java-тесты и Node runner, интерфейсы Postman и IntelliJ отдельно не запускались.

## Учётные записи

`POST /api/security/register`: `username`, `name`, `email`, `password`. Перед регистрацией тоже нужен CSRF. Результат содержит ID, имя и email, но не хеш или пароль. Логин и email уникальны без учёта регистра; роль всегда USER, присланные role/state не повышают права. Исходный `POST /api/users` сохранён для ADMIN: он принимает те же четыре поля и создаёт обычного пользователя с учётной записью. Старых name/email без логина и пароля недостаточно.

Пароль: 12–64 символа, заглавная и строчная латинские буквы, цифра и специальный символ; не больше 72 байт UTF-8 из-за ограничения BCrypt. Используется BCrypt с cost=12 и индивидуальной солью.

`GET /api/security/me` показывает текущую учётную запись. HTTP Basic передаётся в каждом запросе. Сессия хранит CSRF, а не вход: cookie без Authorization не даёт доступа. Состояние проверяется при каждом запросе; старый токен не помогает заблокированному пользователю.

`PATCH /api/admin/accounts/{id}/state`, тело `{"state":"LOCKED"}`, доступен ADMIN. Состояния: ACTIVE, DISABLED, LOCKED, EXPIRED, PASSWORD_EXPIRED. Вход разрешён только ACTIVE. Детали причины отказа входа клиенту не сообщаются. Для восстановления нужен ADMIN.

## Права

| Ресурс / действие | USER | ADMIN |
|---|---|---|
| Профили пользователей | Список содержит только себя; чтение и изменение своего | Чтение и изменение всех |
| Создание учётной записи | Регистрация | Регистрация или POST /api/users; ADMIN создаётся локальным bootstrap |
| Предметы | Просмотр; создание для себя; изменение своих | Просмотр, создание и изменение всех |
| Лоты | Просмотр; создание и изменение лотов своих предметов | Все лоты |
| Ставки | Просмотр; создание только от своего имени | Те же правила создания, нельзя обходить бизнес-ограничения |
| Сделки | Чтение продавцом/победителем; создание и завершение продавцом | Чтение, создание, изменение |
| Удаление любого CRUD-ресурса | Запрещено | Разрешено, с исходными каскадными удалениями |
| Состояния аккаунтов | Запрещено | Разрешено |

SecurityFilterChain ограничивает маршруты, роли и публичные точки; @PreAuthorize стоит на методах сервиса CRUD и методах управления аккаунтом. Access проверяет владельца, текущего участника и продавца конкретного лота. Нельзя отправить чужой userId в ставке. Чужие профили и сделки не раскрываются: прямой запрос получает одинаковый 403 независимо от существования скрытой записи, списки фильтруются. Идентификаторы ставок и владельцев нужны для публичной истории аукциона; email других пользователей USER не получает.

## Бизнес-правила

Цены положительны, окончание позже начала, предмет имеет не больше одного лота. Ставки принимаются только в OPEN между startTime и endTime. Продавец не может ставить на свой предмет; новая ставка не меньше текущей плюс шаг. Ставки неизменяемы. После первой ставки нельзя менять условия лота. Законченный или отменённый лот нельзя повторно открыть. Предмет открытого лота нельзя редактировать.

Продавец может явно закрыть свой лот раньше endTime — так работала исходная лабораторная, это сохранено. Сделка создаётся после закрытия или наступления endTime, только с максимальной ставкой и точной суммой. Отменённый лот не позволяет создать сделку. Передача PENDING → COMPLETED меняет владельца предмета на победителя; условия сделки и завершённая передача неизменяемы. Исходный продавец сохраняется отдельно, чтобы права на сделку не переходили вместе с предметом. Запись ставок синхронизирована внутри одного экземпляра приложения.

## Ответы и хранение

- 401 — нет входа, неверный пароль или недопустимое состояние; одинаковое сообщение и WWW-Authenticate.
- 403 — недостаточно прав или неверный/отсутствующий CSRF у вошедшего пользователя.
- 400 — неправильный JSON, обязательные поля, форматы и слабый пароль.
- 404 — отсутствующий доступный ресурс.
- 409 — дубликат регистрации или нарушение бизнес-правила.

Если в защищённом запросе одновременно отсутствуют вход и CSRF, возвращается 401. CSRF действует и на регистрацию. Ответы не содержат паролей, хешей, SQL или трассировок. Неожиданная ошибка даёт общее 500.

H2 создаёт `data/auction.mv.db` относительно рабочей папки. В таблице accounts — учётные записи и хеши. Исходные карты аукциона сохранены в коде, их снимок записывается в таблицу auction_state и восстанавливается при старте. В schema.sql задан WRITE_DELAY=0, чтобы не откладывать запись подтверждённых изменений ([документация H2](https://h2database.com/html/commands.html#set_write_delay)). Это учебное приложение для одного процесса; не запускайте два экземпляра на одной базе. Тесты используют отдельную базу в памяти. Для чистой демонстрации можно после остановки приложения переименовать папку data; это создаст новую базу при следующем запуске.

HTTP Basic предназначен здесь для локальной демонстрации; при сетевом размещении нужен HTTPS. В репозиторий сдавайте исходники, pom.xml, README, коллекцию и инструкции. Не включайте data, target, .idea и собственные пароли; app.jar — готовая сборка для запуска, в GitHub необязателен.
